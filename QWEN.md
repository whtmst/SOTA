- **БЕЗОПАСНОСТЬ ИЗМЕНЕНИЙ (CRITICAL):**

    - **ТОЧЕЧНОСТЬ:** Используй `replace` (с 3 строками контекста) для врезки кода. **ЗАПРЕЩЕНО** перезаписывать файл целиком (`write_file`) ради мелкой правки. `write_file` - только для _новых_ файлов.
- **ОТВЕЧАТЬ ТОЛЬКО НА РУССКОМ ЯЗЫКЕ**

- **НЕПРИКОСНОВЕННОСТЬ КОММЕНТАРИЕВ:** При редактировании (`replace`) захватывай в `old_string` комментарии, чтобы вернуть их в `new_string` неизменными. Удаление комментариев = сбой.
- **РАБОТА С ФАЙЛОВОЙ СИСТЕМОЙ И SHELL:**
    - Использовать `echo` или `> file` в PowerShell **СТРОГО ЗАПРЕЩЕНО** (ломает кодировку UTF-8).
    - Создание/правка файлов - **ТОЛЬКО** через встроенные инструменты (`write_file`, `replace`).
    - **РАЗРЕШЕНО** использовать PowerShell (`Get-Content`, `Get-ChildItem`, `Select-String`) **ТОЛЬКО ДЛЯ ЧТЕНИЯ** локальных справочников и поиска нужных функций (см. пункт 5).

## 3. Стандарты кода (LUA 5.0 - STRICT!)

- **СИНТАКСИС СТРОГО LUA 5.0.** Клиент 1.12.1 не поддерживает функции из Lua 5.1+.
- **ЗАПРЕЩЕНО:** Оператор длины таблицы `#table` (используй `table.getn(t)`), оператор остатка от деления `%` (используй `math.mod(a, b)`).
- **ЛОКАЛЬНОСТЬ:** Все переменные и функции должны быть `local` по умолчанию, чтобы не засорять глобальную область видимости `_G`.
- Глобальные переменные используй только для инициализации самого аддона или глобальных фреймов.
- **ЗАПРЕЩЕНО `this` в замыканиях (`SetScript`):** В обработчиках событий используй явную ссылку на фрейм из замыкания.
  - ❌ `frame:SetScript("OnClick", function() this:Hide() end)` → может вызвать `ACCESS_VIOLATION`
  - ✅ `frame:SetScript("OnClick", function() frame:Hide() end)` → стабильно работает
- Обработка строк: используй базовый `string.find`, `string.sub`, `string.format`.

## 5. API и база знаний (NO HALLUCINATIONS - CRITICAL)

- **НЕ ВЫДУМЫВАТЬ ФУНКЦИИ.** API клиента 1.12.1 сильно урезан по сравнению с актуальным WoW.
- **ИСПОЛЬЗУЙ АЛЬМАНАХ:** В папке проекта есть специальная директория `_IGNORE\_WOW_API_ALMANACS`. В ней лежит полная база доступных функций 1.12 и специфичных функций сервера Turtle WoW.
    - Перед тем как написать вызов API, в котором ты не уверен на 100%, **ОБЯЗАН** использовать PowerShell для поиска в этой папке. Пример: `Select-String -Path "_IGNORE\_WOW_API_ALMANACS\*.txt" -Pattern "GetMasterLootCandidate"`.
- **ИСПОЛЬЗУЙ PFUI ДЛЯ ПРИМЕРОВ UI:** В папке `_IGNORE\_WOW_API_ALMANACS\AddOns\pfUI` лежит исходный код современного интерфейса для 1.12.
    - Если нужно понять, как правильно отрендерить сложный фрейм, хукнуть функцию интерфейса или сделать современную анимацию/кнопку средствами 1.12, **ОБЯЗАН** найти аналог в исходниках `pfUI` через PowerShell и изучить их подход.
- **ОБХОД GITIGNORE (CRITICAL):**
    - Так как справочники и исходники находятся в директории `_IGNORE`, они скрыты от стандартного поиска.
    - При вызове любых инструментов поиска или чтения файлов в этих папках **ВСЕГДА** передавай параметр `respect_git_ignore: false`. Без этого параметра ты не увидишь содержимое папок.
    - Пример использования инструмента read_file:
    ```

      "path": "D:\\CODING\\Turtle WoW\\MRT\\_IGNORE\\_WOW_API_ALMANACS\\AddOns\\AutoMarker",
    ```

## 6. Безопасность и совместимость

- Осторожно с переопределением глобальных функций WoW (Hooking). Всегда используй безопасный подход (сохраняй старую функцию в переменную перед перезаписью, вызывай ее внутри новой).
- Исключай конфликты с другими популярными аддонами на 1.12.
- Защита данных: проверяй наличие значений (nil checks) перед операциями с таблицами, чтобы аддон не сыпал Lua-ошибками в интерфейс игрока.
- **НИЛ-ПРОВЕРКИ (CRITICAL):** Перед любым обращением к вложенным объектам (`self.raidPanel.topContainer`, `button.text`, `profile.raidPanel` и т.д.) **ОБЯЗАТЕЛЬНО** проверяй на nil. Это предотвращает ACCESS_VIOLATION (Error 132) при холодном старте или ошибке инициализации.
  - ✅ `if self.raidPanel.topContainer then self.raidPanel.topContainer:Hide() end`
  - ❌ `self.raidPanel.topContainer:Hide()` → может вызвать ACCESS_VIOLATION если topContainer = nil

## 7. Веб-интерфейс -> WoW UI (FrameXML / Lua)

- Создание UI преимущественно через `CreateFrame()` в Lua, минимизация использования внешних `.xml` файлов (если это не продиктовано спецификой задачи).
- Якоря (`SetPoint`), размеры (`SetWidth`, `SetHeight`) и текстуры (`SetTexture`).
- Никаких "наэкранных стилей" из веба. Изучай реализацию в `pfUI` для создания кастомных Backdrop'ов, рамок и шрифтов.

## 8. Файлы и данные (SavedVariables)

- Хранение данных между сессиями реализуется **ТОЛЬКО** через `SavedVariables` или `SavedVariablesPerCharacter` в `.toc` файле.
- Избегай сохранения избыточных данных. Таблицы для сохранения должны быть максимально плоскими и легкими, чтобы не увеличивать время загрузки клиента.

## 9. Производительность (OnUpdate)

- **ОСТОРОЖНО С `OnUpdate`:** Скрипты, висящие на `OnUpdate`, выполняются каждый кадр (до 60+ раз в секунду).
- Внутри `OnUpdate` **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** создавать новые таблицы (`{}`) или вызывать тяжелые функции поиска, чтобы не провоцировать сборщик мусора (GC) и микрофризы клиента.
- Используй троттлинг (таймеры с накоплением `arg1`) для логики, которой не нужно выполняться каждый кадр (например, обновление UI раз в 0.5 сек.).

- **ДРОВЕЦ ПРОЕКТА:** Крыло `mrt`, Комната: `design`, `core`, `libs`, `locales`, `frontend`, `general`.
- **АВТО-СЕЙВ (CRITICAL):**
    - Агент **ОБЯЗАН** сохранять ключевые моменты в MemPalace **самостоятельно**, без команды пользователя.
    - **КОГДА СОХРАНЯТЬ:**
        - После завершения этапа/подзадачи.
        - При принятии архитектурных решений.

        - При обнаружении багов и их исправлении.

    - **ИНСТРУМЕНТЫ:** `mempalace_add_drawer` (основной), `mempalace_search` (поиск), `mempalace_diary_write` (мысли/заметки агента).
    - `silent_save: true` - хуки настроены на тихое сохранение.

## 16. Caveman Mode - ВСЕГДА АКТИВЕН

### АКТИВАЦИЯ (ПРИОРИТЕТ)
**Режим Caveman full включается АВТОМАТИЧЕСКИ сразу при получении этого файла.** Не ждать команду `/caveman full`. Не спрашивать пользователя. Первый ответ после загрузки контекста - уже в стиле caveman full. Расширение установлено, но Qwen Code не поддерживает авто-хуки - это правило в QWEN.md является триггером.

### Правила
- Убрать: артикли, filler (just/really/basically), любезности (sure/certainly/happy to), hedging.
- Оставить: фрагменты OK, короткие синонимы, технические термины без изменений. Код без изменений.
- Паттерн: `[вещь] [действие] [причина]. [следующий шаг].`
- НЕ: «Конечно помогу! Скорее всего проблема в...»
- ДА: «Баг в auth middleware. Проверка expiry: `<` вместо `<=`. Фикс:»

### Уровни (по команде)
- **lite** - без filler/hedging. Грамматика полная. Профессионально.
- **full** (дефолт) - без артиклей, фрагменты, короткие синонимы. Классический caveman.
- **ultra** - аббревиатуры (DB/auth/config/fn/impl), стрелки причинности (X → Y), одно слово когда достаточно.

### Auto-Clarity
Drop caveman для: предупреждения безопасности, необратимые действия, мульти-степ последовательности, пользователь переспрашивает. После - resume caveman.

### Границы
Код/коммиты/PR - обычный формат. «stop caveman» / «normal mode» - отключение. Уровень держится до смены или конца сессии.
